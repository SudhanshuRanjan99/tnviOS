# Tnvios API Standards

Version: 1.0

Status: Platform Standard

Classification: Architecture Standard

---

# Purpose

This document defines API standards for all Tnvios services, modules, AI agents, mobile applications, and third-party integrations.

Goals:

* Consistency
* Security
* Scalability
* Versioning
* Discoverability
* Developer Experience

All APIs must follow this standard.

---

# API Architecture

Tnvios uses:

REST APIs (Primary)

Event APIs (Internal)

Webhooks (External)

GraphQL (Future)

AI Tool APIs (Future)

---

# API Principles

## Resource Based

APIs represent business resources.

Good:

```text
/customers
/projects
/invoices
```

Bad:

```text
/createCustomer
/getAllProjects
```

---

## Predictable

Every module follows the same conventions.

---

## Versioned

Every API must be versioned.

Format:

```text
/api/v1/
```

Example:

```text
/api/v1/crm/customers
```

---

## Stateless

Every request contains all required context.

No server-side API state.

---

# URL Structure

Format:

```text
/api/v{version}/{module}/{resource}
```

Examples:

```text
/api/v1/crm/customers

/api/v1/hr/employees

/api/v1/finance/invoices

/api/v1/projects/tasks
```

---

# HTTP Methods

GET

Retrieve resources.

POST

Create resources.

PUT

Replace resources.

PATCH

Partial updates.

DELETE

Soft delete resources.

---

# Resource Naming

Use plural nouns.

Good:

```text
/customers

/employees

/invoices
```

Bad:

```text
/customer

/getCustomers
```

---

# CRUD Standards

Create

```http
POST /api/v1/crm/customers
```

Read

```http
GET /api/v1/crm/customers/{id}
```

Update

```http
PATCH /api/v1/crm/customers/{id}
```

Delete

```http
DELETE /api/v1/crm/customers/{id}
```

---

# Response Standard

Every response follows the same structure.

---

## Success Response

```json
{
  "success": true,
  "data": {},
  "meta": {}
}
```

---

## Collection Response

```json
{
  "success": true,
  "data": [],
  "meta": {
    "page": 1,
    "pageSize": 25,
    "total": 100
  }
}
```

---

## Error Response

```json
{
  "success": false,
  "error": {
    "code": "CUSTOMER_NOT_FOUND",
    "message": "Customer not found"
  }
}
```

---

# Soft Delete Standard

Records are never physically deleted.

Required fields:

```sql
deleted_at
deleted_by
```

DELETE APIs mark records deleted.

# Enterprise Platform API Addendum

Tnvios APIs must support full enterprise platform capabilities across every module.

Required shared APIs:

```text
/api/v1/onboarding/flows
/api/v1/onboarding/progress
/api/v1/help/contexts
/api/v1/help/tours
/api/v1/activity
/api/v1/comments
/api/v1/comments/{id}/mentions
/api/v1/inbound-email/messages
/api/v1/imports
/api/v1/exports
```

Import/export APIs must enforce tenant isolation, organization isolation, record-level permissions, field-level permissions, audit logging, background job processing, signed file URLs, and event publishing.

Inbound email APIs must validate signed reply tokens, sender identity, tenant context, entity access, action permission, attachment safety, and audit requirements before executing any action.

Comments and mentions APIs must validate that mentioned users can access the target entity before notifications are sent.
